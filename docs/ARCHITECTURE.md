# AI Trader 项目架构文档

## 1. 整体架构视角

本项目采用**分层架构 + 微内核模式**，以"数据驱动决策"为核心设计理念，将量化交易系统划分为清晰的职责层。

```
┌─────────────────────────────────────────────────────────────┐
│                     表现层 (Presentation)                     │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │   Web UI     │  │   API Docs   │  │  Scheduler   │      │
│  │  (Next.js)   │  │  (Swagger)   │  │ (APScheduler)│      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
├─────────────────────────────────────────────────────────────┤
│                     应用层 (Application)                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐       │
│  │ 策略引擎 │ │ 回测引擎 │ │ ML引擎   │ │ AI服务   │       │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘       │
├─────────────────────────────────────────────────────────────┤
│                     领域层 (Domain)                          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐       │
│  │ 股票模型 │ │ 因子计算 │ │ 信号生成 │ │ 日志系统 │       │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘       │
├─────────────────────────────────────────────────────────────┤
│                     基础设施层 (Infrastructure)               │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐       │
│  │ SQLite   │ │ Local CSV│ │  AkShare │ │ XGBoost  │       │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘       │
└─────────────────────────────────────────────────────────────┘
```

## 2. 核心模块解析

### 2.1 前端模块 (Frontend)

**定位**: 用户交互层，采用 **Next.js 14 App Router** 架构

**模块划分**:
```
frontend/
├── app/
│   ├── dashboard/
│   │   ├── page.tsx          # 首页仪表盘
│   │   ├── stocks/           # 行情中心
│   │   ├── factors/          # 因子中心
│   │   ├── strategies/       # 策略中心
│   │   ├── signals/          # 交易信号
│   │   ├── backtest/         # 回测中心
│   │   ├── market/           # 市场结构
│   │   ├── ml/               # ML预测
│   │   ├── news/             # 资讯中心
│   │   ├── ai/               # AI服务
│   │   └── settings/         # 系统设置
│   ├── services/api.ts       # 统一API客户端
│   └── layout.tsx            # 根布局
```

**设计思路**:
- **全客户端渲染** (`'use client'`)：量化数据实时性强，服务端渲染意义不大
- **统一API层**：所有后端调用通过 `api.ts` 集中管理，便于拦截和日志
- **导航即模块**：侧边栏11个导航项对应11个独立功能模块

---

### 2.2 后端模块 (Backend)

**定位**: 业务逻辑层，采用 **FastAPI + 分层架构**

#### 2.2.1 API层 (`api/v1/endpoints/`)

| 模块 | 职责 | 核心端点 |
|------|------|----------|
| `stocks.py` | 股票数据管理 | CRUD、价格查询、数据同步 |
| `factors.py` | 因子计算与管理 | 561个因子的计算、筛选、排名 |
| `strategies.py` | 策略生命周期 | 创建、启停、执行、删除 |
| `signals.py` | 交易信号管理 | 生成、确认、执行、分级 |
| `backtest.py` | 回测引擎 | 运行回测、获取结果、权益曲线 |
| `ml.py` | 机器学习 | 模型训练、预测、性能评估 |
| `ai.py` | AI服务 | 股票分析、策略生成、情感分析 |
| `market.py` | 市场结构 | 行业轮动、情绪指数、风险预警 |
| `localdata.py` | 本地数据导入 | CSV导入、预览、批量处理 |
| `logs.py` | 日志查询 | 操作日志、错误日志、统计 |
| `strategy_optimizer.py` | 策略优化 | 网格搜索、滚动优化 |

**设计思路**:
- **RESTful + 动词后缀**：如 `/{id}/start`, `/{id}/stop` 表示状态转换
- **查询参数用于过滤**：`?industry=银行&market=SH`
- **统一响应格式**：`{total, items}` 或 `{error}`

#### 2.2.2 服务层 (`services/`)

**核心服务**:

```python
# 数据服务 - 处理股票基础数据
class StockDataService:
    - get_stocks()          # 获取股票列表
    - sync_stock_list()     # 同步股票列表
    - import_local_data()   # 导入本地CSV

# 因子服务 - 561个因子的计算引擎
class FactorService:
    - calculate_all_factors()   # 计算所有因子
    - screen_by_factor()        # 因子筛选
    - get_factor_values()       # 获取因子值

# 策略服务 - 策略执行与信号生成
class StrategyService:
    - execute_strategy()        # 执行策略
    - generate_signals()        # 生成信号
    - get_buy_grade()          # 买点评级

# 回测服务 - 历史数据验证
class BacktestService:
    - run_backtest()            # 运行回测
    - calculate_metrics()       # 计算指标
    - optimize_params()         # 参数优化

# ML服务 - 预测模型
class MLService:
    - train_model()             # 训练XGBoost
    - predict()                 # 预测涨跌
    - get_feature_importance()  # 特征重要性

# 策略优化器 - 自动调参
class StrategyOptimizer:
    - optimize_strategy()       # 单策略优化
    - walk_forward_test()       # 滚动前向测试
    - auto_optimize_all()       # 批量优化
```

**设计思路**:
- **Service类作为领域对象**：每个Service对应一个业务领域
- **数据库会话注入**：通过参数传递 `db: Session`，保持无状态
- **日志装饰器**：`@log_operation` 自动记录调用和性能

#### 2.2.3 核心层 (`core/`)

| 模块 | 职责 |
|------|------|
| `config.py` | 配置管理，环境变量映射 |
| `database.py` | SQLAlchemy ORM、模型定义、会话管理 |
| `logger.py` | 结构化日志系统 |
| `security.py` | 安全相关（预留） |

**数据模型关系**:
```
Stock (1) ────────< (N) DailyPrice
   │
   │ (1) ────────< (N) FactorData
   │
   │ (N) ────────< (N) Strategy ──────< (N) Signal
                          │
                          └──────────< (N) BacktestResult
```

## 3. 模块交互关系

### 3.1 核心业务流程

#### 策略执行流程
```
用户创建策略 ──> StrategyService.validate()
                    │
                    ▼
            StrategyService.execute()
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   技术指标计算  因子评分      ML预测
        │           │           │
        └───────────┴───────────┘
                    │
                    ▼
            SignalService.generate()
                    │
                    ▼
            买点评级 (1-5级)
                    │
                    ▼
            保存到 DB + 推送通知
```

#### 回测流程
```
选择策略 ──> BacktestService.run_backtest()
                │
                ▼
        加载历史数据 (Local CSV)
                │
                ▼
        逐日模拟交易
                │
        ┌───────┴───────┐
        ▼               ▼
    买入信号        卖出信号
        │               │
        ▼               ▼
    更新持仓        计算收益
        │               │
        └───────┬───────┘
                ▼
        生成权益曲线
                │
                ▼
        计算指标 (Sharpe/Drawdown/WinRate)
                │
                ▼
        保存 BacktestResult
```

#### 策略优化流程
```
触发优化 ──> StrategyOptimizer.optimize_strategy()
                    │
                    ▼
            生成参数组合网格
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    [5,20]      [10,60]     [20,120]
    参数1       参数2        参数3
        │           │           │
        └───────────┴───────────┘
                    │
                    ▼
            对每个参数运行回测
                    │
                    ▼
            比较性能指标 (Sharpe)
                    │
                    ▼
            选择最优参数
                    │
                    ▼
            更新 Strategy.params
```

## 4. 扩展性设计

### 4.1 新增策略类型

要新增一个策略类型（如 `KDJ金叉`），需要：

1. **后端**
   - `services/strategy_service.py`: 添加 `kdj_cross` 执行逻辑
   - `services/strategy_optimizer.py`: 添加参数范围
   - `api/v1/endpoints/strategies.py`: 添加 preset 配置

2. **前端**
   - `app/dashboard/strategies/page.tsx`: 添加策略卡片

3. **数据**
   - `factor_service.py`: 确保 KDJ 因子已计算

### 4.2 新增因子

要新增一个因子（如 ` custom_factor`）：

1. **定义因子** (`services/factor_service.py`):
```python
def calculate_custom_factor(self, code: str, df: pd.DataFrame) -> pd.Series:
    # 实现因子计算
    return df['close'] / df['ma20']
```

2. **添加到分类**:
```python
FACTOR_CATEGORIES = {
    "custom": {
        "custom_factor": {"name": "自定义因子", "formula": "close/ma20"}
    }
}
```

3. **前端自动展示**（因子中心自动读取API返回的分类）

## 5. 关键设计决策

### 5.1 为什么用 SQLite 而不是 PostgreSQL？

- **单机部署简单**：用户无需配置数据库服务
- **数据量可控**：股票数据存在CSV，SQLite只存元数据
- **Python原生支持**：零依赖，便于分发

### 5.2 为什么用本地CSV而不是全部存数据库？

- **性能**：历史数据量大（5822只股票×4000天=2300万行），CSV查询更快
- **灵活性**：可以直接用 pandas 读取，便于ML训练
- **可移植性**：CSV可以单独备份、迁移

### 5.3 为什么用 Next.js 而不是纯 React？

- **API Proxy**：Next.js rewrite 解决跨域问题
- **文件路由**：pages/ 目录自动对应路由
- **生态成熟**：TypeScript + Tailwind 集成好

### 5.4 为什么日志用 JSON Lines？

- **结构化**：便于程序解析和查询
- **可读性**：人类也能直接阅读
- **扩展性**：可以轻松添加新字段而不破坏旧日志

## 8. 总结

本项目采用 **分层 + 模块化** 设计，核心特点：

1. **前后端分离**：前端专注交互，后端专注计算
2. **领域驱动**：Service 类对应业务领域（策略、因子、回测）
3. **数据分层**：CSV存历史，SQLite存元数据，API取实时
4. **可观测性**：全链路日志记录，便于调试和审计
5. **可扩展性**：新增策略/因子只需修改对应模块，不影响其他

每个模块都有清晰的 **单一职责**，通过 **API契约** 进行交互，便于独立测试和维护。
